# 3x-ui Clash 分流规则

将 OpenClash 上游模板转换为可与 3x-ui 面板订阅合并的 Clash/Mihomo 全局路由片段，适合需要业务分流、自定义规则和节点分类的用户。

## 使用方法

- `Custom_Clash_3xui.yaml`：用于面板的远程全局路由配置，保留面板提供的 `PROXY` 组。
- `Custom_Clash_3xui_inline.yaml`：用于粘贴到面板的内联全局路由配置，包含动态 `PROXY` 组。

根据面板支持的配置方式选择其中一份，保存后刷新客户端订阅。这些文件只包含策略组、规则集和分流规则，不包含节点，必须与面板生成的订阅合并使用。客户端需支持 Mihomo 的 `include-all-proxies`、`filter` 和 `exclude-filter`，具体面板入口以所用版本为准。

## 节点分组

节点按名称自动分为两个手动选择组：

- **原生IP**：名称严格以大写 `WNTT` 结尾，例如 `香港-WNTT`。
- **机房IP**：其余节点，例如 `香港-01`、`WNTT-日本` 和 `香港-wntt`。

社交媒体、ChatGPT、AI服务、TikTok、国外电商和即时通讯默认选择“原生IP”；“手动选择”默认选择“机房IP”。默认选项放在各组候选列表首位；客户端已有保存的手动选择时，需在客户端切换到相应分组。

这是按名称约定分类，不检测实际 IP 属性。手动选择及代理业务组中均可选择这两个组，也可以继续选择单个节点或使用原有自动测速。分类组的节点选择状态由引用它的业务组共享；需要业务独立选点时，可在对应业务组中直接选节点。没有符合条件的节点时，该分类无可选节点。

## 自定义规则

编辑 `custom_rules.yaml` 中的 `rules` 列表。自定义规则按填写顺序优先匹配，目标可以是 `DIRECT`、`REJECT`、`PROXY` 或生成配置中的策略组名称，例如：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,原生IP
  - DOMAIN-SUFFIX,example.net,机房IP
```

提交并推送自定义规则后，GitHub Actions 会更新两份配置；工作流也会定时同步上游。不要将节点密钥或订阅凭据写入规则文件。

本地生成、校验和维护方法见 [开发说明](Development.md)。
